1) CONTEXTO GENERAL
-------------------------------------------------------------------------------
Proyecto: ConsultorioClinico — Sistema de control médico y clínico.
Monorepo con:
  - frontend/   Aplicación en Flutter (web/móvil), despliegue en Firebase.
  - backend/    API REST en Node.js + Express, despliegue en Vercel
                (vercel.json incluido). Base de datos Supabase (PostgreSQL).
  - docs/       Documentación del proyecto.
  - prompt.txt / prompt-modulos.txt / prompt-progreso.txt  Prompts de trabajo.

Stack backend: Express 4, @supabase/supabase-js 2, bcryptjs, jsonwebtoken,
express-validator 7, helmet, cors, compression, morgan, dotenv.

Arquitectura backend (backend/src):
  app.js                  Instancia Express + montaje de rutas (exporta para Vercel)
  server.js               Arranque local (único punto que escucha el puerto)
  config/config.js        Config por entorno (JWT_SECRET, JWT_EXPIRE, SUPABASE_*)
  config/supabase.js      Cliente Supabase singleton (service_role) + testConnection()
                          + dbErrorMessage() traduce errores PostgREST a mensajes claros
  controllers/            Un controlador por módulo (auth, paciente, medico,
                          especialidad, horario, cita, disponibilidad, consulta,
                          pago, reporte, dashboard)
  middleware/auth.js      verifyToken (JWT Bearer obligatorio) + optionalAuth
                          (decodifica token si viene; nunca falla)
  middleware/roles.js     checkRole(...roles) -> 403 si req.user.rol no está permitido
  middleware/validation.js validate() centraliza express-validator + validadores
                          reutilizables (cita, horario, pagos, params id/fecha...)
  routes/                 Un router por módulo, montados bajo /api/<modulo>
  utils/constants.js      ROLES, ESTADOS_CITA, METODOS_PAGO, ESTADOS_PAGO,
                          DIAS_SEMANA, INTERVALO_CITA_MINUTOS=30
  utils/helpers.js        sendSuccess/sendError (respuesta JSON estándar),
                          formatDate, obtenerDiaSemana, horaAMinutos/minutosAHora...
  views/ + public/        Landing institucional EJS (login.ejs, citas, medicos...)

Roles del sistema (utils/constants.js -> ROLES):
  admin | medico | recepcion | paciente

Respuesta JSON estándar:
  Éxito: { success: true, message, data }
  Error: { success: false, message, errors? }

001_initial_schema.sql

  - usuarios: id, nombre, email UNIQUE, password (hash bcrypt), rol CHECK IN

3) AUTENTICACIÓN Y ROLES (backend/src/controllers/authController.js)
-------------------------------------------------------------------------------
Endpoints (montados en /api/auth):

POST /api/auth/register   [público con optionalAuth]
  - Reglas de seguridad:
    * Registro público SOLO crea rol 'paciente' (rol default si no se envía).
    * Si se pide rol admin/medico/recepcion se EXIGE Bearer token de un admin;
      si no, responde 403 "Solo un administrador puede crear usuarios con
      roles privilegiados". (Evita auto-elevación de privilegios.)
  - Email normalizado (trim+lowercase) en rutas y BD (trigger 003).
  - Valida email único (400 si duplicado). Password hasheada bcrypt (salt 10).
  - Si el rol es medico o paciente crea su fila de perfil asociada
    (medicos/pacientes.usuario_id) de forma tolerante a fallos.
  - Devuelve { id, nombre, email, rol, perfil:{tipo,id}, token }.

POST /api/auth/login      [público]
  - Validaciones express-validator: email válido (trim+lowercase),
    password obligatoria. Errores -> 422.
  - Usuario no existe o password incorrecta -> 401 'Credenciales inválidas'.
  - usuario.activo = false -> 403 'Cuenta desactivada...'.
  - Login case-insensitive de email (normalización en ruta + controlador + BD).
  - Resuelve perfil vinculado (medico/paciente) por usuario_id.
  - Firma JWT con payload { id, email, rol, perfilTipo, perfilId, jti },
    expiración según JWT_EXPIRE (default 24h).
  - Auditoría (mejor esfuerzo, no bloquea): usuarios.ultimo_acceso=NOW() e
    INSERT en sesiones (jti, ip, user_agent, expira_en).

GET /api/auth/profile     [verifyToken]
  - Devuelve datos del usuario autenticado + perfil {tipo,id} + ultimo_acceso.

POST /api/auth/logout     [verifyToken]
  - Marca la sesión (token_id=jti) como activa=false, cerrada_en=NOW().
  - Nunca falla para el cliente (logout stateless si la tabla no existe).

Middleware:
  - verifyToken: exige Bearer; valida firma/expiración (401 Token expirado /
    inválido). Carga req.user = payload decodificado.
  - checkRole('admin',...): compara req.user.rol; 401 si no autenticado,
    403 listando roles requeridos.
  - optionalAuth: decodifica token si viene y es válido; nunca rechaza.

  POST / , PUT /:id , DELETE /:id            admin

/api/horarios   (MIGRADO de mockData a Supabase en esta sesión)
  GET /                        público
  GET /disponibles             público (horarios activos de médicos activos)
  GET /medico/:medicoId        público
  POST                         admin (valida horas coherentes y solapamiento
                                     por médico/día contra la BD -> 409)
  PUT /:id                     admin (valida solapamiento excluyendo el propio)
  DELETE /:id                  admin

/api/citas      (estados alineados a la BD: programada|en_curso|completada|
                 cancelada|no_show)
  GET /                    admin, recepcion
  GET /agenda/hoy          admin, medico
  GET /medico/:id          público (valida existencia del médico)
  GET /paciente/:id        público (valida existencia del paciente)
  GET /:id                 público
  POST                     admin, recepcion, paciente
    - Verifica paciente exista (404), médico exista y activo (404/400).
    - Rechaza fechas pasadas (400).
    - Valida que el médico atienda ese día/hora según horarios en BD (400).
    - Verifica doble agenda (query + índice único parcial de BD -> 400).
  PUT /:id                 admin, recepcion, paciente (reprogramar)
    - Rechaza reprogramar completadas/canceladas; mismas validaciones de
      fecha/horario/disponibilidad excluyendo la propia cita.
  PATCH /:id/estado        admin, recepcion, medico (CHECK de estados válidos)
  DELETE /:id              admin, recepcion (marca 'cancelada')

/api/disponibilidad   (MIGRADO de mockData a Supabase en esta sesión)
  GET /medico/:medicoId/fecha/:fecha   público (valida medicoId y fecha YYYY-MM-DD)
    - Rechaza fechas pasadas (400).
    - Genera slots de 30 min según horarios activos del día en BD, descarta
      horas pasadas si es hoy y slots ya reservados (citas no canceladas).
    - Devuelve { medico_id, medico, fecha, dia_semana, intervalo_minutos,
      slots_disponibles[], total_disponibles }.
  GET /especialidad/:especialidadId    público (valida especialidadId)
    - Médicos activos de esa especialidad (catálogo) + días_atencion
      (unión de sus horarios activos).

/api/consultas
  GET /paciente/:id   público
  GET /:id            público
  POST                admin, medico
  PUT /:id            admin, medico

/api/pagos
  GET /               admin, recepcion
  GET /paciente/:id   público
  POST                admin, recepcion

/api/reportes
  GET /citas           filtros fecha_inicio/fecha_fin/medico_id/especialidad/

  GET /ingresos        filtros fecha/metodo_pago sobre pagos 'pagado'

/api/dashboard
  GET /                resumen (citas de hoy, completadas, pendientes, etc.)

/api/health  GET  público.  Ruta raíz "/" lista todos los endpoints.

  npm install
